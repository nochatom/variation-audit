# Decision: Shared Evidence Type Vocabulary (.21.1)

> Task: `variation-audit-z3x.21.1` · Parent: `.21` · Status: **accepted** (2026-06-27)
> Extends [engine-product-api-contract-v1](../engine-product-api-contract-v1.md). Fixes the input/output enum mismatch.

## 1. Problem
Contract v1 used two different vocabularies:
- Input `documents[].type`: `email | rfi | site_instruction | meeting_note | sms | document`
- Output `evidence[].type`: `email | rfi | instruction | note`

An `sms`- or `document`-sourced variation could not cite its source faithfully, and `instruction`/`note` were ambiguous synonyms.

## 2. Decision — One Canonical `source_type` Enum
A single enum is used by **both** `documents[].type` (input) and `evidence[].type` (output):

| value | meaning |
|-------|---------|
| `email` | email message or thread |
| `rfi` | request for information + its response |
| `site_instruction` | architect / engineer / superintendent instruction issued on site |
| `meeting_note` | meeting minutes or notes |
| `sms` | SMS / text message |
| `document` | generic document (PDF, DOCX, image, other) — catch-all |

- **Deprecated → removed:** output `instruction` (→ `site_instruction`) and `note` (→ `meeting_note`).
- The enum is **closed** for v1 (unknown inputs must be mapped to `document`, not invented).

## 3. Source Traceability (`document_id`)
Type alone is not enough to trace evidence to its origin. Add an id linkage:
- Input: each `documents[]` item MAY carry a client `document_id` (string). If absent, the engine assigns a stable one.
- Output: each `evidence[]` item MUST include `source_document_id` referencing the originating input document, in addition to the human-readable `reference` and `quote`.

### Updated evidence shape
```json
{
  "type": "email | rfi | site_instruction | meeting_note | sms | document",
  "source_document_id": "string",
  "reference": "string (human-readable locator)",
  "quote": "string excerpt"
}
```

## 4. Scope
- Vocabulary is part of `contract_version: v1`; adding a new source type is a contract change.
- Engine and product layer share this enum from a single definition (one source file / generated type), not duplicated literals.
